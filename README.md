# AI Dashboard

Дашборд корпоративных систем с индикаторами статуса, режимом редактирования по PIN и переключением светлой/тёмной темы.

## Стек

- React 19 + TypeScript
- Vite 8

## Docker (рекомендуется для постоянной работы)

```bash
# остановить локальный сервер, если был запущен
docker compose down

# собрать и запустить
npm run docker:build
npm run docker:up
```

Дашборд: `http://localhost:3102` (или IP вашего ПК в сети).

Данные систем хранятся в `./data/systems.json` (монтируется в контейнер).

```bash
npm run docker:logs   # логи
npm run docker:down   # остановка
```

Другой порт снаружи:

```bash
$env:PORT=8080; docker compose up -d --build
```

> Health-check внутренних адресов (`192.168.x.x`) из контейнера идёт через сеть Docker. Если сервисы недоступны из контейнера, на Linux можно добавить в `docker-compose.yml`: `network_mode: host`.

## Запуск без Docker

```bash
npm install
npm run dev
```

Откроется фронтенд на `http://localhost:5173`, API health-check — на `http://localhost:3102`.

В консоли сервера будут показаны **Network**-адреса — по ним коллеги в локальной сети могут открыть дашборд с других компьютеров.

## Доступ из локальной сети (рекомендуется)

Для постоянной работы на вашем ПК в корпоративной сети:

```bash
npm run start:lan
```

Это соберёт фронтенд и запустит единый сервер на порту **3102** (доступен по `0.0.0.0`).

Коллеги открывают в браузере, например:

```text
http://192.168.1.50:3102
```

IP-адрес смотрите в выводе консоли после запуска (строка `Network:`).

### Windows: открыть порт в брандмауэре

PowerShell **от имени администратора**:

```powershell
cd d:\Aidashboard
.\scripts\open-firewall.ps1
```

Для режима разработки (`npm run dev`, порт 5173):

```powershell
.\scripts\open-firewall-dev.ps1
```

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HOST` | `0.0.0.0` | Интерфейс для прослушивания (все сетевые адаптеры) |
| `PORT` | `3102` | Порт сервера |

Пример:

```bash
set PORT=8080 && npm start
```

## Продакшен

```bash
npm run build
npm start
```

Сервер раздаёт `dist/` и API на порту `3102` (или `PORT` из окружения).

Список систем хранится в `data/systems.json` на сервере — общий для всех пользователей в сети. Редактирование защищено PIN-кодом.

## Мониторинг доступности

- Браузер не умеет ICMP ping и блокирует прямые cross-origin запросы, поэтому проверка идёт через backend `POST /api/health-check`.
- Для каждой системы можно указать отдельный **URL для проверки** (например `/health` или `/api/status`).
- Если поле пустое — проверяется основная ссылка.
- Сервер делает HTTP `HEAD`, при `405/501` — fallback на `GET`.
- Успех: HTTP `200–399`. Таймаут: 8 секунд. Автообновление: каждые 30 секунд.
- Если мониторинг выключен — статус «Нет счётчика» (жёлтый), проверка не выполняется.

## Возможности

- Список систем: название, ссылка, описание, статус (онлайн / офлайн / нет счётчика)
- Реальная проверка доступности через HTTP health-check на backend
- Настраиваемый URL проверки для каждой системы
- Цветовые индикаторы: зелёный, красный, жёлтый
- Режим редактирования по PIN (кнопка замка в правом верхнем углу)
- Переключение светлой и тёмной темы
- Адаптивная вёрстка для десктопа и мобильных устройств
- Данные систем хранятся на сервере в `data/systems.json`
