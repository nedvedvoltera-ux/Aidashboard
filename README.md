# AI Dashboard

Дашборд корпоративных систем с индикаторами статуса, режимом редактирования по PIN и переключением светлой/тёмной темы.

## Стек

- React 19 + TypeScript
- Vite 8

## Docker (рекомендуется для постоянной работы)

```bash
# остановить локальный сервер, если был запущен
docker compose down

# собрать и запустить
npm run docker:build
npm run docker:up
```

Дашборд: `http://localhost:3102` (или IP вашего ПК в сети).

Данные систем хранятся в `./data/systems.json` (монтируется в контейнер).

```bash
npm run docker:logs   # логи
npm run docker:down   # остановка
```

Другой порт снаружи:

```bash
$env:PORT=8080; docker compose up -d --build
```

> Health-check внутренних адресов (`192.168.x.x`) из контейнера идёт через сеть Docker. Если сервисы недоступны из контейнера, на Linux можно добавить в `docker-compose.yml`: `network_mode: host`.

## Запуск без Docker

```bash
npm install
npm run dev
```

Откроется фронтенд на `http://localhost:5173`, API health-check — на `http://localhost:3102`.

В консоли сервера будут показаны **Network**-адреса — по ним коллеги в локальной сети могут открыть дашборд с других компьютеров.

## Доступ из локальной сети (рекомендуется)

Для постоянной работы на вашем ПК в корпоративной сети:

```bash
npm run start:lan
```

Это соберёт фронтенд и запустит единый сервер на порту **3102** (доступен по `0.0.0.0`).

Коллеги открывают в браузере, например:

```text
http://192.168.1.50:3102
```

IP-адрес смотрите в выводе консоли после запуска (строка `Network:`).

### Windows: открыть порт в брандмауэре

PowerShell **от имени администратора**:

```powershell
cd d:\Aidashboard
.\scripts\open-firewall.ps1
```

Для режима разработки (`npm run dev`, порт 5173):

```powershell
.\scripts\open-firewall-dev.ps1
```

### Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HOST` | `0.0.0.0` | Интерфейс для прослушивания (все сетевые адаптеры) |

Пример:


## Продакшен

```bash
npm run build
npm start
```

Сервер раздаёт `dist/` и API на порту `3102` (или `PORT` из окружения).

Список систем хранится в `data/systems.json` на сервере — общий для всех пользователей в сети. Редактирование защищено PIN-кодом.

## Мониторинг доступности

- Браузер не умеет ICMP ping и блокирует прямые cross-origin запросы, поэтому проверка идёт через backend `POST /api/health-check`.
- Для каждой системы можно указать отдельный **URL для проверки** (например `/health` или `/api/status`).
- Если поле пустое — проверяется основная ссылка.
- Сервер делает HTTP `HEAD`, при `405/501` — fallback на `GET`.
- Успех: HTTP `200–399`. Таймаут: 8 секунд. Автообновление: каждые 30 секунд.
- Если мониторинг выключен — статус «Нет счётчика» (жёлтый), проверка не выполняется.

## Мониторинг виртуальных машин

Раздел «Виртуальные машины» показывает загрузку CPU, памяти, диска и время работы (uptime) реальных серверов —
без установки на дашборд каких-либо драйверов или SSH-клиентов. Всё, что нужно, — это агент сбора метрик
Prometheus **на самой ВМ**:

- **Linux** — [node_exporter](https://github.com/prometheus/node_exporter), порт по умолчанию `9100`.
- **Windows** — [windows_exporter](https://github.com/prometheus-community/windows_exporter), порт по умолчанию `9182`.

Как подключить:

1. Скачайте и запустите exporter на сервере, который нужно мониторить (для Linux — просто бинарник, для
   Windows — MSI-инсталлятор).
2. Откройте порт агента (`9100`/`9182`) в файрволе для доступа с машины, где работает дашборд.
3. В интерфейсе дашборда, в режиме редактирования, нажмите «+ Добавить ВМ» и укажите адрес метрик:
   `http://<IP-ВМ>:9100/metrics` (Linux) или `http://<IP-ВМ>:9182/metrics` (Windows).
4. Дашборд сам определяет тип exporter'а по содержимому ответа, опрашивает его каждые 30 секунд
   (`VM_POLL_INTERVAL_MS`) и считает CPU % по разнице счётчиков между двумя опросами.

Статусы: «Онлайн» — метрики получены и в норме; «Высокая нагрузка» (оранжевый) — CPU, память или диск ≥ 85%;
«Офлайн» — exporter недоступен; «Нет счётчика» — мониторинг выключен для этой записи.

Эта же логика подробно расписана прямо в интерфейсе — разворачивающийся блок «Как подключить реальную
виртуальную машину» над списком ВМ.

## Мониторинг LLM-сервисов

Раздел «LLM-сервисы» проверяет не просто «открыт ли порт», а что языковая модель реально готова отвечать —
дашборд запрашивает список загруженных моделей у сервиса:

- **OpenAI-совместимый API** (vLLM, LM Studio, text-generation-webui, LocalAI и т.п.) — `GET {baseUrl}/v1/models`.
- **Ollama** — `GET {baseUrl}/api/tags`.
- **Свой путь** — любой endpoint, отвечающий `200 OK`, когда сервис готов принимать запросы.

Как подключить:

1. В режиме редактирования нажмите «+ Добавить LLM-сервис», укажите название и базовый адрес без пути
   (например `http://192.168.1.20:11434` для Ollama).
2. Выберите тип проверки, соответствующий вашему API.
3. Если API требует авторизацию — **не вводите сам ключ в форму**. Задайте переменную окружения с ключом
   на сервере дашборда (в `docker-compose.yml` или `.env`) и укажите в поле формы только имя переменной,
   например `OPENAI_API_KEY`. Ключ никогда не попадает в `data/llms.json` и не отображается в интерфейсе.
4. Дашборд опрашивает сервис каждые 45 секунд (`LLM_POLL_INTERVAL_MS`), таймаут — 15 секунд
   (`LLM_PROBE_TIMEOUT_MS`), так как холодный старт модели может быть небыстрым.

Подробная инструкция также доступна прямо в интерфейсе — блок «Как подключить реальный LLM-сервис».

## Мониторинг Docker

Раздел «Docker» показывает состояние контейнеров (работает / остановлен / healthcheck) на хосте, где работает
дашборд, или на удалённом хосте — **только на чтение**, без возможности останавливать или перезапускать
контейнеры из интерфейса.

Как подключить:

- **Дашборд в Docker Compose**: раскомментируйте в `docker-compose.yml` строку монтирования сокета —
  ```yaml
  volumes:
    - /var/run/docker.sock:/var/run/docker.sock:ro
  ```
  и пересоберите: `docker compose up -d --build`.
- **Дашборд на Windows напрямую** (`npm run dev` / `npm start`) с установленным Docker Desktop — подключение
  к именованному каналу `\\.\pipe\docker_engine` происходит автоматически, ничего настраивать не нужно.
- **Удалённый Docker-хост**: включите на нём TCP-доступ к Docker Engine API (только в защищённой сети/VPN,
  например `dockerd -H tcp://0.0.0.0:2375`) и укажите на сервере дашборда переменную окружения
  `DOCKER_HOST=tcp://<адрес>:2375`.

Если Docker Engine API недоступен, в интерфейсе будет чёткое сообщение об этом и та же инструкция —
блок «Как подключить мониторинг Docker» над разделом.

## Возможности

- Список систем: название, ссылка, описание, статус (онлайн / офлайн / нет счётчика)
- Реальная проверка доступности через HTTP health-check на backend
- Настраиваемый URL проверки для каждой системы
- **Мониторинг производительности ВМ** (CPU, RAM, диск, uptime) через node_exporter / windows_exporter
- **Мониторинг доступности LLM-сервисов** (OpenAI-совместимый API, Ollama, свой путь)
- **Мониторинг состояния Docker-контейнеров** через Docker Engine API (только чтение)
- Цветовые индикаторы: зелёный, красный, оранжевый (высокая нагрузка), жёлтый
- Встроенные в интерфейс инструкции по подключению реальных узлов для каждого типа мониторинга
- Режим редактирования по PIN (кнопка замка в правом верхнем углу)
- Переключение светлой и тёмной темы
- Адаптивная вёрстка для десктопа и мобильных устройств
- Данные систем хранятся на сервере: `data/systems.json`, `data/vms.json`, `data/llms.json`

## Переменные окружения (мониторинг)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `HEALTH_CHECK_TIMEOUT_MS` / `HEALTH_POLL_INTERVAL_MS` | `8000` / `30000` | Таймаут и период опроса систем |
| `VM_PROBE_TIMEOUT_MS` / `VM_POLL_INTERVAL_MS` | `8000` / `30000` | Таймаут и период опроса ВМ (exporter) |
| `LLM_PROBE_TIMEOUT_MS` / `LLM_POLL_INTERVAL_MS` | `15000` / `45000` | Таймаут и период опроса LLM-сервисов |
| `DOCKER_POLL_INTERVAL_MS` / `DOCKER_PROBE_TIMEOUT_MS` | `20000` / `6000` | Период и таймаут опроса Docker Engine API |
| `DOCKER_SOCKET_PATH` | `/var/run/docker.sock` (Linux) или именованный канал (Windows) | Свой путь к сокету Docker |
| `DOCKER_HOST` | — | `tcp://host:port` для удалённого Docker Engine API |
